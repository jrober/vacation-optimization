Live prices — how to plug in real APIs later

This prototype deliberately does not call live APIs and does not store keys in code. To go live, fill in the fields below (they stay in your browser only, in this page session) and implement the placeholder functions in the page source. Until then, estimates are used.

Placeholder fetch functions (in source)

fetchLiveFlight() → Duffel Offers API (POST https://api.duffel.com/air/offers).
fetchLiveHotel() → your hotel booking API (e.g. Booking.com / Expedia partner API) for nightly rates by date.
fetchLiveCruise() → cruise line / aggregator API for sailing price by departure date and cabin.
Each should return a per-date price in the same shape as the estimate functions, or null to fall back to estimates. Keep keys out of git — use environment variables / a server proxy in production, never a client-side key in a public page.

How the estimate works

  • Flight: base round-trip per adult, adjusted by weekday (Tue/Wed cheapest, Fri/Sun dearest), season by month, and a deterministic pseudo-random variation per date + destination — so the same search always gives the same ranking.
  • Hotel: nightly rate, with a weekend (Fri/Sat night) premium, season, and the same per-date variation.
  • Cruise: per person, by trip length — 3-night style, 4–5-night style, or 7+ night style — children at 50% of the adult cruise price.
  • Total = flight + hotel + cruise for the selected components. Per-person = total ÷ (adults + children). Savings = most-expensive window total − this window total.
